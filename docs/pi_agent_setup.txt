Diegimas nuo nulio: ubuntu server 24.04 (raspberry pi 5), botas veikia kaip atskiras
vartotojas piagent be sudo teisiu, apribotas systemd.
Komandas rasykite po vieną. Nekopijuokite eiluciu ```.

Prepare the Python Environment
	sudo apt install git python3-pip python3-venv -y
-----------------------------------------------
Sukurkite vartotoja piagent (be sudo, be slaptazodzio):
	sudo adduser --disabled-password --gecos "" piagent
	sudo chmod 700 /home/piagent
Patikrinkite, kad zodzio sudo nera:
	id piagent
-----------------------------------------------
Prieigos raktas prie GitHub (deploy key, tik skaitymas, saugykla privati):
	sudo -u piagent mkdir -m 700 /home/piagent/.ssh
	sudo -u piagent ssh-keygen -t ed25519 -N "" -C "raspi-deploy-key" -f /home/piagent/.ssh/id_ed25519
	sudo cat /home/piagent/.ssh/id_ed25519.pub
Nukopijuokite visa eilute (ssh-ed25519 ... raspi-deploy-key) i GitHub:
	https://github.com/SimonasKairys/pi_agent/settings/keys
	Add deploy key, Title: raspi, Allow write access NEZYMETI, Add key.
Patikrinkite rysi:
	sudo -u piagent ssh -o StrictHostKeyChecking=accept-new -T git@github.com
(turi buti: Hi SimonasKairys/pi_agent! You've successfully authenticated ...)
Privataus rakto (failas be .pub) niekur nesiuskite.
Kuriant nauja raktą (pvz. po SD korteles gedimo), sena raktą pasalinkite tame pačiame GitHub
puslapyje (Delete prie seno rakto).

Nuklonuokite projekta (aplankas turi buti tuscias arba neegzistuoti):
	sudo -u piagent git clone git@github.com:SimonasKairys/pi_agent.git /home/piagent/telegram-agent
Jei aplankas jau yra, pirma pervadinkite:
	sudo -u piagent mv /home/piagent/telegram-agent /home/piagent/telegram-agent.old

Kad docs/ neatsirastu Raspberry Pi (kiti failai ir nauji aplankai isskleidziami kaip ipratai):
	sudo -u piagent git -C /home/piagent/telegram-agent sparse-checkout set --no-cone '/*' '!/docs/'
Nustatymas vietinis: klonuodami is naujo, komanda pakartokite. Patikrinkite:
	sudo -u piagent ls /home/piagent/telegram-agent
(docs/ neturi buti)

-----------------------------------------------
Slaptus raktus laikykite ne agento kataloge, o root failu.
Create the secrets file:
	sudo mkdir -p /etc/piagent
	sudo nano /etc/piagent/env

Paste (be kabuciu, be tarpu aplink =, savo reiksmes):
OPENROUTER_API_KEY=jusu_openrouter_raktas
TELEGRAM_BOT_TOKEN=jusu_telegram_tokenas
TAVILY_API_KEY=jusu_tavily_raktas
COMPOSIO_API_KEY=jusu_composio_raktas
COMPOSIO_CONNECTED_ACCOUNT_ID=prijungtos_paskyros_id

Kintamuju paaiskinimai:
- OPENROUTER_API_KEY: OpenRouter API raktas modelio kvietimams.
- TELEGRAM_BOT_TOKEN: Telegram boto tokenas is @BotFather.
- TAVILY_API_KEY: Tavily API raktas paieskai internete.
- COMPOSIO_API_KEY: Composio API raktas kalendoriaus irankiu vykdymui (su Tool execution: Write leidimu).
- COMPOSIO_CONNECTED_ACCOUNT_ID: Composio prijungtos Google Calendar paskyros identifikatorius (formatas ca_...).

Google Calendar prijungimas per Composio (app.composio.dev):
	1. Prijunkite Google Calendar paskyra. Google sutikimo lange palikite pazymetus VISUS
	   leidimus ir patvirtinkite pilna kalendoriaus leidima
	   https://www.googleapis.com/auth/calendar (tik calendar.events nepakanka).
	   Savo Google OAuth programai ta pati leidima pridekite prie sutikimo ekrano;
	   testavimo rezime savo paskyra itraukite tarp test users.
	2. Nukopijuokite prijungtos paskyros ID (ca_...) i COMPOSIO_CONNECTED_ACCOUNT_ID.
	   Perjungus paskyra ID paprastai pasikeicia.
	3. COMPOSIO_API_KEY turi turėti Tool execution: Write leidima.
	4. Po env pakeitimo: sudo systemctl restart piagent
Jei kalendorius atsako "insufficient authentication scopes" (ACCESS_TOKEN_SCOPE_INSUFFICIENT,
method calendar.v3.Calendars.Get) -> per siaura Google leidimai: perjunkite paskyra
Composio su pilnu leidimu ir atnaujinkite ID. Skaitymas gali veikti, o kurimas ne.
Laikas: irankiai siuncia vietini laika be UTC poslinkio ir atskira zona (Europe/Vilnius);
jei ivykis atsiranda 3 val. anksciau, patikrinkite, ar dedate naujausia koda (git pull).

Kas gali naudotis botu: /etc/piagent/users.toml
Anksciau tam buvo TELEGRAM_ALLOWED_USER_IDS aplinkos kintamasis. Jo nebera:
botas skaito tik si faila, o kiekvienas vartotojas turi varda, el. pasta ir
laiko juosta. Vardai privalo buti unikalus, nes modelis dalyvius nurodo vardais.

	sudo nano /etc/piagent/users.toml

Paste (savo reiksmes):
[[user]]
telegram_id = 111111111
name = "Simonas"
email = "vardas@example.com"
timezone = "Europe/Vilnius"
role = "admin"

[[user]]
telegram_id = 222222222
name = "Ruta"
email = "ruta@example.com"
timezone = "Europe/Vilnius"
role = "member"

Svečiai (nebutini): zmones, kuriuos galima kviesti i kalendoriaus ivykius, bet kurie
botu nesinaudoja (neturi telegram_id, prieigos prie boto negauna). Tame paciame faile:

[[guest]]
name = "Jonas"
email = "jonas@example.org"

Vardai privalo buti unikalus tarp vartotoju IR svecių. Agentas kviecia tik vartotojus ir
svecius is saraso pagal varda; el. pasto adreso, kurio saraše nera, jis pridėti negali.
Svecio pasalinus is failo, jo dalyvaujanciu ivykiu keisti nebegalima (kol nepasalinsite
jo is ivykio arba nepridesite atgal), o naujai nekviesiamas.
Duomenu baze: naujas lentele event_guests (schema v4), sukuriama automatiskai paleidus nauja koda.

Apribokite teises (procesas skaito, bet perrasyti negali):
	sudo chown root:piagent /etc/piagent/users.toml
	sudo chmod 640 /etc/piagent/users.toml

Pakeitus faila reikia perkrauti paslauga:
	sudo systemctl restart piagent
Jei faile yra klaida (pasikartojantis vardas, bloga laiko juosta, el. pastas be @),
botas nestartuoja ir priezasti iraso i zurnala:
	sudo journalctl -u piagent -n 20 --no-pager
-----------------------------------------------
Create the service file:
	sudo nano /etc/systemd/system/piagent.service

Paste:
[Unit]
Description=Pi agent Telegram bot
After=network-online.target
Wants=network-online.target

[Service]
User=piagent
Group=piagent
WorkingDirectory=/home/piagent/telegram-agent
ExecStart=/home/piagent/telegram-agent/venv/bin/python bot.py
EnvironmentFile=/etc/piagent/env
Restart=on-failure
RestartSec=5

ProtectSystem=strict
ReadWritePaths=/home/piagent
ProtectHome=tmpfs
BindPaths=/home/piagent
InaccessiblePaths=/root /media /mnt /srv

PrivateTmp=true
PrivateDevices=true
ProtectProc=invisible
ProcSubset=pid
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true
NoNewPrivileges=true
CapabilityBoundingSet=
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX
RestrictSUIDSGID=true
UMask=0077

[Install]
WantedBy=multi-user.target

Check the file:
	sudo systemd-analyze verify /etc/systemd/system/piagent.service
(jei nieko neisveda, failas geras)

Naktine konsolidacija (atskira paslauga, ne boto dalis). Papildomus apribojimus
(ProtectSystem ir kt.) galite nukopijuoti is `systemctl cat piagent.service`.
Failuose privalo buti visos sekcijos ([Unit], [Service], [Timer], [Install]), kitaip
systemctl rodo "bad unit file setting" arba "no installation config".
Paslauga:
	sudo systemctl edit --force --full piagent-consolidate.service
Paste:
[Unit]
Description=Nightly memory consolidation
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
User=piagent
Group=piagent
EnvironmentFile=/etc/piagent/env
WorkingDirectory=/home/piagent/telegram-agent
ExecStart=/home/piagent/telegram-agent/venv/bin/python -m agent.consolidate

(be [Install]: paslauga paleidziama laikmaciu. EnvironmentFile butinas: be jo
OpenAIError "Missing credentials", nes .env Raspberry Pi nera.)
Laikmatis:
	sudo systemctl edit --force --full piagent-consolidate.timer
Paste:
[Unit]
Description=Nightly memory consolidation timer

[Timer]
OnCalendar=*-*-* 03:00:00 Europe/Vilnius
Persistent=true

[Install]
WantedBy=timers.target

(03:00, 30 min. pries kopijavima 03:30, kad irasai patektu i tos nakties kopija.
Laikas su zona, kitaip OnCalendar naudoja sistemos zona.)
Ijungimas ir patikra:
	sudo systemctl daemon-reload
	sudo systemctl enable --now piagent-consolidate.timer
	systemctl list-timers piagent-consolidate.timer
(turi rodyti kita 03:00 EEST/EET)
Bandymas dabar:
	sudo systemctl start piagent-consolidate.service
	sudo journalctl -u piagent-consolidate.service -n 15 --no-pager
(pabaigoje: "Naktine konsolidacija baigta"; "zinuciu nera" reiskia, kad per paras nebuvo pokalbiu)
Jei neveikia:
	Refusing to start, unit ... not loaded -> nera .service failo su tuo paciu pavadinimu
	bad unit file setting -> trukstamos sekcijos; patikra: sudo systemd-analyze verify /etc/systemd/system/piagent-consolidate.timer
	Missing credentials -> truksta EnvironmentFile=/etc/piagent/env
	Persistent=true po ijungimo gali paleisti papildoma praleista paleidima (nekenksminga)

Duomenu bazes (SQLite) patikra: /home/piagent/data/agent.db
Lenteles: messages, summaries, facts, events, event_attendees, event_guests, pending_approvals, usage.
Naudokite -readonly ir sudo -u piagent; nekeiskite duomenu, kol botas veikia.
	sudo apt install -y sqlite3
	sudo -u piagent sqlite3 -readonly /home/piagent/data/agent.db ".tables"
Irasu skaicius:
	sudo -u piagent sqlite3 -readonly /home/piagent/data/agent.db "SELECT 'messages', COUNT(*) FROM messages UNION ALL SELECT 'summaries', COUNT(*) FROM summaries UNION ALL SELECT 'facts', COUNT(*) FROM facts UNION ALL SELECT 'events', COUNT(*) FROM events UNION ALL SELECT 'usage', COUNT(*) FROM usage;"
Naujausi irasai:
	sudo -u piagent sqlite3 -readonly -header -column /home/piagent/data/agent.db "SELECT * FROM messages ORDER BY rowid DESC LIMIT 5;"
	sudo -u piagent sqlite3 -readonly -header -column /home/piagent/data/agent.db "SELECT id, title, starts_at, deleted_at FROM events ORDER BY id DESC LIMIT 5;"
Vientisumas:
	sudo -u piagent sqlite3 -readonly /home/piagent/data/agent.db "PRAGMA integrity_check;"
(turi buti: ok)
Patikra: parasykite botui zinute ir pakartokite messages skaiciavima: skaicius turi padideti.
Istrintas ivykis lieka events lenteleje su uzpildytu deleted_at (minkstas trynimas).
